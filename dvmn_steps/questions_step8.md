# Уточняющие вопросы по контракт-паку (step 8)

## 1. Пользователи
В карточках концептов нет сущности «Пользователь/Ученик/Преподаватель». В схеме student_id — внешний UUID без FK. Нужна ли таблица users с ролью (student, teacher, admin)?

## 2. Ревью
Есть поле reviewer_comment в student_works, но нет отдельной сущности «Ревью». Нужна ли таблица reviews с историей проверок (reviewee, reviewer, verdict, комментарии)?

## 3. Прогресс по шагам
student_progresses фиксирует только текущий урок. Нужна ли таблица step_completions для отслеживания, какие шаги ученик прошёл?

## 4. Группы и расписание
У groups нет полей для расписания/дат доступа. Нужны ли они, или группа — только логический ярлык для разграничения видимости курса?

## 5. Дедлайны уроков
У lessons есть deadline и deadline_type. Дедлайн — один на урок. Нужна ли поддержка разных дедлайнов для разных групп учеников внутри одного курса?

## 6. Автор курса
В карточках упоминается «автор», но нет поля author_id. Нужна ли связь курса с пользователем-автором?

## 7. Категории работ
В концепте «Работа ученика» перечислены 9 категорий (на ревью, проверенная, принятая, на доработке, просроченная, черновик, тест, интерактивная, кодирование). В схеме status покрывает только 5 состояний жизненного цикла, а тип работы (тест/кодирование/интерактив) не моделируется. Нужно ли поле work_type?
