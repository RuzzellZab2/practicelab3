Берём платформу edx.org. Какие возможности платформа даёт автору урока?
Перечисли списком. Минимум 10 пунктов, лучше больше.

Автор урока отвечает за контент, но не за монетизацию/маркетинг.

Ответ:

Возможности edX (Open edX Studio) для автора урока (18 пунктов):

1. Создание видеолекций — загрузка видео, настройка субтитров, транскриптов, замедление/ускорение
2. Текстовые страницы (HTML) — написание теории с форматированием, изображениями, LaTeX, встроенными ссылками
3. Задачи с автопроверкой — multiple choice, checkbox, dropdown, числовой ввод, text input, drag-and-drop
4. Задачи на программирование (CodeGrader) — автопроверка кода через встроенный grader (Python, Java, C++, MATLAB и др.)
5. Задачи с Math Expression Input — ввод формул через встроенный редактор
6. Peer Assessment (Open Response Assessment) — письменные задания с взаимопроверкой по рубрике
7. Рубрикатор (Rubric) — автор задаёт критерии и уровни оценки для peer assessment
8. Настройка дедлайнов — мягкие/жёсткие дедлайны на уровне секций, подсекций, юнитов
9. Условное открытие (Gating) — следующий модуль открывается после сдачи предыдущего; можно настроить по баллам, по времени
10. Sequential navigation — автор задаёт порядок прохождения: последовательно или свободно (в любой последовательности)
11. Группировка в Section → Subsection → Unit — иерархическая структура курса
12. Настройка проходного балла — автор устанавливает минимальный % для сертификата
13. Повторные попытки — настройка количества попыток на задачу, штраф за попытку
14. Подсказки (Hints) — к задачам можно добавлять текстовые подсказки, открывающиеся по запросу
15. Аналитика (edX Insights) — просмотр статистики: распределение оценок, время на видео, успешность задач, воронка прохождения
16. Форумы и обсуждения — встроенные форумы для каждого курса, модерация, ответы автора
17. Content Libraries — переиспользуемые блоки контента между курсами (как общий банк заданий)
18. LTI-интеграция — встраивание внешних инструментов (симуляторы, лаборатории, сторонние виджеты)

Отфильтрованный список (прямо связаны с категориями концептов):

1. Задачи с автопроверкой (multiple choice, checkbox, числовой ввод и др.) → концепт «Шаг» (ответить, выполнить)
2. Задачи на программирование (CodeGrader) → концепт «Шаг» (выполнить, отправить, получить проверку)
3. Задачи с Math Expression Input → концепт «Шаг» (ответить)
4. Peer Assessment (взаимопроверка) → категория «Урок с ревью»
5. Рубрикатор (Rubric) → категория «Урок с ревью» (критерии оценки)
6. Настройка дедлайнов → категории «Пройденный/текущий урок», «Курс» (влияют на статус)
7. Условное открытие (Gating) → категория «Урок» (пройденный открывает следующий), «Курс» (последовательность)
8. Sequential navigation → «Первый/последний урок», «Пройденный урок» (порядок прохождения)
9. Настройка проходного балла → категории «Завершённый курс», «Пройденный урок»
10. Повторные попытки и штрафы → концепт «Шаг» (регулирует выполнение)
11. Подсказки (Hints) → концепт «Шаг» (помогает выполнить)

Статусная модель для описания управления доступом (курсы и уроки):

Статусы Курса (для ученика):
1. Недоступен — ученик не зачислен / курс ещё не начался (стартовая дата не настала)
2. Доступен — ученик может зайти и начать обучение
3. В процессе — хотя бы один урок начат
4. Завершён — все обязательные уроки пройдены, набран проходной балл
5. Просрочен — финальный дедлайн курса истёк, доступ закрыт

Статусы Урока (для ученика):
1. Заблокирован — предыдущий урок не пройден / дедлайн старта не настал / не набран нужный уровень mastery
2. Доступен — ученик может начать, но ещё не начал
3. В процессе — ученик открыл, выполняет шаги
4. На проверке — работа отправлена на ревью, ожидает проверки
5. Пройден — ученик выполнил все критерии (набрал балл, прошёл шаги)
6. Провален — дедлайн истёк / превышен лимит попыток / mastery не достигнута за отведённое время
7. Пропущен — урок не обязательный (опциональный), ученик может его не проходить

| Хотелка | Обстоятельства | Связь с концептами |
|---|---|---|
| Написать текстовую теорию (HTML) | Ученику нужно прочитать объяснение перед практикой | **Шаг** — единица «прочитать»; **Урок** — контейнер текстовых шагов |
| Записать и загрузить видео | Текста недостаточно, нужна видеолекция | **Шаг** — формат «посмотреть»; **Урок** — набор видеошагов |
| Создать задачу с автопроверкой | Ученик должен ответить и сразу узнать результат | **Шаг** — ученик «отвечает, выполняет»; проверка определяет прогресс по **Уроку** |
| Добавить задачу на код (CodeGrader) | Ученик пишет программу, тесты проверяют её без автора | **Шаг** — «отправить, получить проверку»; результат — условие прохождения **Урока** |
| Добавить задачу с формулой | Для точных наук нужен ввод математических выражений | **Шаг** — формат «ответить» с формульным вводом |
| Настроить взаимопроверку (Peer Assessment) | Работу ученика должен оценить другой ученик по критериям | **Урок с ревью** — категория урока, где работа попадает на проверку |
| Настроить рубрикатор | Нужны чёткие критерии, чтобы ревьюеры оценивали одинаково | **Урок с ревью** — рубрикатор задаёт рамки оценки |
| Установить дедлайны на модули | Нужно ограничить время сдачи, чтобы курс шёл по графику | **Урок** (пройденный/текущий) — дедлайн влияет на статус; **Курс** — общий график |
| Настроить условное открытие (Gating) | Следующий модуль должен открываться только после сдачи предыдущего | **Пройденный урок** — статус триггерит доступ; **Курс** — последовательность |
| Выбрать порядок прохождения (Sequential) | В одном курсе уроки идут строго, в другом — свободно | **Первый/последний урок** — границы; **Курс** — упорядоченный набор |
| Настроить проходной балл | Нужно определить, при каком % ученик считается прошедшим | **Завершённый курс** — условие завершения; **Пройденный урок** |
| Ограничить число попыток | Ученик не должен бесконечно угадывать ответ | **Шаг** — лимит попыток регулирует выполнение |
| Добавить подсказки (Hints) | Ученик застрял, нужна помощь без готового ответа | **Шаг** — подсказка помогает выполнить шаг |
