Возможности Stepik для автора урока (18 пунктов):

1. Создание текстовой теории с форматированием (Markdown/HTML, формулы LaTeX, вставка изображений)
2. Встраивание видео с YouTube, Vimeo или загрузка собственного видеофайла
3. Интерактивные вставки (виджеты, симуляторы, внешние iframe)
4. Задачи с выбором одного/нескольких вариантов ответа
5. Задачи с числовым или текстовым вводом (автопроверка)
6. Задачи на сортировку и сопоставление
7. Задачи на заполнение пропусков и таблицы соответствия
8. Задачи на код с автопроверкой (30+ языков, sandbox, юнит-тесты)
9. Задачи на SQL с реальной тестовой БД
10. Задания-эссе с ручной проверкой преподавателем
11. Peer-review (взаимопроверка учениками) с анонимностью и калибровкой
12. Рубрикатор (Rubric) — настраиваемые критерии оценки для эссе
13. Шаблоны решений и стартовый код для задач
14. Многоуровневая система подсказок («лесенка») с ценой открытия
15. Условная навигация — следующий урок открывается после сдачи предыдущего
16. Дедлайны и расписание (мягкие/жёсткие границы для модулей и уроков)
17. Просмотр статистики — распределение попыток, среднее время, сложность, распределение ответов
18. Группы учащихся с отдельной статистикой и расписанием

Отфильтрованный список (только фичи, прямо связанные с концептами PracticeLab и полезные автору контента):

1. Задачи на код с автопроверкой → концепт «Шаг» (выполнить, отправить, получить проверку)
2. Peer-review / взаимопроверка → концепт «Урок с ревью» (работа попадает на проверку)
3. Рубрикатор (Rubric) → концепт «Урок с ревью» (критерии оценки)
4. Многоуровневые подсказки («лесенка») → концепт «Шаг» (помогает выполнить шаг)
5. Условная навигация → концепт «Урок», «Курс» (последовательность, прогресс)
6. Дедлайны и расписание → концепт «Урок», «Курс» (прогресс, прохождение)
7. Статистика по задачам (попытки, время, сложность) → концепт «Шаг» (анализ выполнения)
8. Группы учащихся с отдельной статистикой → концепт «Курс» (кто проходит)
9. Шаблоны решений и стартовый код → концепт «Шаг» (начальное состояние)
10. Задания-эссе с ручной проверкой → концепт «Шаг» (отправить) + «Урок с ревью»

❌ Повторная фильтрация: фичи, НЕ покрытые существующими категориями концептов (относятся к автору курса):

1. Задачи на код с автопроверкой — нет категории «шаг с автопроверкой»
2. Peer-review — нет категории «шаг/урок с взаимопроверкой»
3. Рубрикатор — нет категории «урок с рубрикатором»
4. Многоуровневые подсказки — нет категории «шаг с подсказками»
5. Условная навигация — нет категории «урок/курс с условным открытием»
6. Дедлайны и расписание — нет категории «урок/курс с дедлайном»
7. Статистика по задачам — нет категории «шаг со статистикой выполнения»
8. Группы учащихся — нет категории «курс для группы»
9. Шаблоны решений — нет категории «шаг с шаблоном»

| Хотелка | Обстоятельства | Связь с концептами |
|---|---|---|
| Написать теорию к уроку | Автор создаёт контент, который ученик должен прочитать перед практикой | **Шаг** — минимальная единица «прочитать»; **Урок** — контейнер таких шагов |
| Прикрепить иллюстрацию к объяснению | Текста недостаточно, нужен скриншот/схема | **Шаг с иллюстрацией** — категория шага, где автор вкладывает визуальное пояснение |
| Добавить чеклист самопроверки | Ученик должен сам проверить свою работу перед отправкой | **Шаг с чеклистом самопроверки** — категория шага; автор пишет критерии |
| Настроить автопроверку кода | Ученик пишет код, платформа проверяет его тестами без участия автора | **Шаг** — ученик «выполняет, отправляет»; результат проверки — условие прогресса по **Уроку** |
| Написать подсказки к задаче | Ученик застревает на шаге, нужна помощь без подглядывания в решение | **Шаг** — подсказка помогает выполнить шаг; влияет на прохождение **Урока** |
| Установить, что урок открывается только после сдачи предыдущего | Автор хочет линейный сценарий: нельзя перепрыгнуть | **Урок** (текущий/пройденный) — статус урока определяет, открыт ли следующий; **Курс** — последовательность уроков |
| Обозначить первый и последний урок курса | Нужно указать границы: с чего начинать и что завершает курс | **Первый урок в курсе**, **Последний урок в курсе** — категории урока; **Курс** — завершается после последнего урока |
| Назначить ревью на урок | Работу ученика должен проверить человек (не автопроверка) | **Урок с ревью** — категория урока; **Шаг** «Отправь работу на ревью» — финальный шаг урока |
| Настроить критерии оценки (рубрикатор) | Нужно, чтобы ревьюеры и ученики понимали, по каким критериям оценивать | **Урок с ревью** — рубрикатор задаёт рамки проверки внутри урока |
| Создать шаблон решения / стартовый код | Ученику нужна заготовка, чтобы не писать с нуля | **Шаг** — начальное состояние шага, ученик «выполняет» на основе шаблона |
| Установить дедлайн на урок | Нужно ограничить время сдачи, чтобы поток не растягивался | **Урок** (пройденный/текущий) — дедлайн влияет на статус урока; **Курс** — дедлайн может завершить курс для ученика |
| Посмотреть статистику: кто сколько попыток сделал | Автор хочет понять, где ученики застревают | **Шаг** — статистика по выполнению шага; **Урок** — анализ проходимости урока; **Курс** — общая картина |
| Собрать группу учеников с отдельным расписанием | Курс идёт для конкретного класса/потока с особыми сроками | **Курс** — группа привязана к курсу, у группы своё расписание и прогресс |
