# Отчёт v11: смысловые ошибки в концептах

Проверка карточек концептов (`concepts/`) после очередного раунда исправлений. Критичных смысловых ошибок в активном содержимом не найдено. Остаются только замечания по полноте и чистке.

## Найденные замечания

### 1. `concepts/student.md:28-30` — «Ученик группы» не подкреплён сценарием (низкий приоритет)

- «Ученик группы» — «ученик, которого Администратор записал в группу», пример «записан в группу „9А“ и **имеет доступ к курсу**».
- Пример неявно связывает «членство в группе → доступ к курсу», но value case для этого пути нет. При этом `group.md` описывает два отдельных действия администратора: «добавил учеников» и «открыл доступ к курсу» — то есть членство в группе и доступ к курсу не одно и то же. Связь «Ученик группы» ↔ «Ученик курса» остаётся неопределённой.

### 2. Нет value cases у ролей «Администратор» и «Владелец» (полнота)

Действия этих ролей описаны в карточках, но не закрыты сценариями:

- Администратор: создать группу, добавить ученика в группу, открыть доступ к курсу (в т.ч. к «Курсу для группы»).
- Владелец: назначить Администратора.

В `admin.md` и `owner.md` нет секции «Value Cases» (в отличие от остальных ролей).

### 3. Закомментированные «остатки» (чистка, не смысловое)

По-прежнему остаются закомментированные блоки: `course.md:22-29`, `lesson.md:35-42`, `student_work.md:46-50`, `reviewer.md:32-36`, `user.md:35-52`. Если это осознанный «след правок» — ок; иначе мёртвый контент лучше удалить.

## Что исправлено в этом раунде

- `course.md:31` — из «Курс для группы» убран «дедлайн» (снято противоречие с `group.md` и пересечение с «Курс с дедлайном»); грамматика «доступ настроен».

## Сводка

- Критичных смысловых ошибок: нет.
- Замечания: 3 (полнота value cases для admin/owner; «Ученик группы» без сценария; закомментированные остатки) — все низкоприоритетные.
