# Концепт: Ученик

Где живет:
- Пользователь (роль student)

Что это:
- Пользователь в роли student. 
- Роль Ученик присваивается всем Пользователям при регистрации на платформе
- Ученик выполняет уроки и шаги курса, к которому этот ученик имеет доступ.

Синонимы:
- Student
- Студент
- Обучающийся

Не путать с:
- Пользователь
  - Почему можно спутать: в речи «ученик сдал работу» и «пользователь сдал работу» звучат одинаково.
  - Почему различаем: пользователь — учётная запись человека; ученик — его роль в системе. Один и тот же пользователь, изначально имея роль ученик, может быть назначен также и ревьюером. 

Вложенные концепты:
- (нет)

Категории:
- Ученик курса
  - Что это: ученик конкретного курса, к которому открыт доступ.
  - Пример: Иван записан на курс «Python» и проходит уроки этого курса.
- Ученик группы
  - Что это: ученик, которого Администратор записал в группу.
  - Пример: ученик записан в группу "9А"
- Должник
  - Что это: ученик курса, который просрочил дедлайн курса
  - Пример: Иван записан на курс «Python» и не смог пройти уроки курса до дедлайна.


Примеры:
- Пример: ученик Иван отправил работу на ревью через веб-сервис — это ученик курса.
- Пример: ученик Иван не сдал работу до дедлайна курса - это ученик-должник.
- Антипример: ревьюер, который проверяет работы, — это не ученик, а другая роль пользователя.

Рамки (границы модели ценности):
- Ученик — роль, а не отдельная учётная запись:
  - out_of_scope: отдельный аккаунт или сущность «ученик» в отрыве от пользователя.
  - why: ученик — фасет пользователя; отдельная сущность дублирует данные и усложняет смену ролей.


# Value Cases

## Value Case: Ученик — записаться на курс
<!-- Входит в v2 - да -->

### Обстоятельства
- Не курс для группы
- Опубликованный курс

### Возможные результаты
- Ученик курса
  - уведомление "Вы имеете доступ к курсу"
  - ссылка на прохождение уроков курса

### Что понадобится
- Веб-сервис — увидеть уведомление о доступе к курсу
- Веб-сервис — увидеть ссылку на прохождение уроков курса


## Value Case: Ученик — выполнить практическую работу
<!-- Входит в v2 - да -->

### Обстоятельства
- Курс не просрочен
- Работа "На доработке"

### Возможные результаты
- Сохраненный черновик работы
  - ученик видит черновик практической работы

### Что понадобится
- Веб-сервис — воспользоваться инструментами для выполнения работы


## Value Case: Ученик — отправить практическую работу на ревью
<!-- Входит в v2 - да -->

### Обстоятельства

### Возможные результаты
- Работа на ревью
  - уведомление "Работа на ревью"
- Неотправленная работа
  - уведомление об ошибке отправки

### Что понадобится
- Веб-сервис — увидеть уведомление "Работа на ревью"
- Веб-сервис — увидеть уведомление об ошибке отправки

### Возможные результаты

### Что понадобится

## Value Case: Ученик — пройти урок
<!-- Входит в v2 - да -->

### Обстоятельства
- Текущий урок

### Возможные результаты
- Пройденный урок
  - ученик видит статус урока "пройден"

### Что понадобится
- Веб-сервис - получить инструменты для прохождения шагов урока
- Веб-сервис — увидеть статус урока "пройден"


## Value Case: Ученик — пройти шаг
<!-- Входит в v2 - да -->

### Обстоятельства
- Начатый шаг

### Возможные результаты
- Пройденный шаг
  - ученик видит уведомление "Шаг пройден"
- Непройденный шаг
  - ученик видит уведомление "Шаг не пройден"

### Что понадобится
- Веб-сервис - увидеть инструменты для выполнения шага c чеклистом самопроверки
- Веб-сервис - увидеть инструменты для выполнения шага с иллюстрацией
- Веб-сервис - увидеть инструменты для выполнения шага с видео
- Веб-сервис - увидеть инструменты для выполнения шага с квизом
- Веб-сервис - увидеть инструменты для выполнения шага с интерактивным заданием
- Веб-сервис — увидеть уведомление "Шаг пройден"
- Веб-сервис — увидеть уведомление "Шаг не пройден"


## Value Case: Ученик — увидеть ревью

## Value Case: Ученик — оставить комментарий к шагу урока
